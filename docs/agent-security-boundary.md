## 2. Trust owners and native scope mapping

**Untrusted inputs:** model plans/tool arguments, ordinary clients, chat/attachments, pages and frames, redirects, provider response bodies, callback payloads, downloads and restored page state. Authentication of a client does not make its claimed scope authoritative. Page instructions and model reasoning cannot widen a grant. The human-only secure-entry surface transports private fields directly to the host; its submitted values remain untrusted data, never policy.

The host must also gate ordinary ingress before model dispatch, chat/history persistence or request logging. Secret-bearing submissions belong only on the private typed input route. Reject sensitive fields and attachments on ordinary Agent routes without echo or retention; return a host-generated secure-entry requirement bound to the original task. Arbitrary text cannot be proven secret-free by a detector alone: an input channel without a qualified admission/filtering policy cannot be used to collect sensitive data, and uncertainty requires withholding its content.

**Authenticated host:** derives tenant, user, project, provider account, environment and purpose from current authenticated principal, native task admission and verified resource bindings. It resolves requested IDs, intersects current authority with the admitted ceiling, enforces item ACLs and domain approvals, owns durable revisions/claims/cancellation and releases sanitized receipts. Tenant is a logical isolation key; in a Handrail organization execution it maps to authenticated `org_id`. Missing scope is denied, not a wildcard. A deliberately personal execution namespace must be explicitly host-derived and isolated from organization execution.

**Qualified trusted executor:** a private server adapter with narrowly authorized decryption, request signing/fill/capture, browser custody and observation filtering. Only this boundary may hold plaintext transiently. It receives a host-bound operation, not a model-controlled raw getter. It must enforce authority and fences at dispatch and output release; inaccessible authority storage or inability to enforce the fence means denial. The executor's provider credentials, filesystem, debug sockets and profiles are unavailable to model/client tools. A remote executor is within the trusted boundary only after its transport, storage, access and telemetry are qualified.

| Native scope | Required Agent mapping |
| --- | --- |
| Personal `vault_entries.user_id`; `org_id`, `project_id`, `env` null | Require current authenticated owner and item authorization. Bind each permitted use separately to the executing tenant/user/project/account/environment/purpose in host-owned grant state. Those are **proposed use bindings**, not invented columns on the personal entry. A personal entry is not automatically usable in every project of its owner. |
| Shared entries with `user_id IS NULL`; project entries carry `org_id/project_id/env` | Validate the native scope plus an explicit item-level use ACL and exact execution binding. Organization membership/sharing and catalog visibility alone do not permit use. Broader org/global entries require an explicit mapping to one execution scope; null native fields never mean unrestricted Agent use. |
| Copy from personal input to shared project/environment | Preserve the source request and both entry identities. Separately authorize the destination and copied item. Copying/submission does not grant execution, prove credential validity, or revoke the original. Revocation policy must explicitly cover dependent grants/copies; never assume a copy inherits authority forever. |

Native task, wake, Vault, provider and domain-effect owners remain authoritative. SDK bindings adapt these owners; they must not create another execution controller, planner or scheduler. The reference Node host must supply equivalent durable authority and isolation; an in-memory map is not cross-process authority.

## 3. Admission, grants and durable identity

These are proposed contract requirements, not existing native grant fields. Persist a use grant with immutable grant ID, current revision, principal and all six scope dimensions, exact item ID/type/version, permitted operation, destination bindings, original job/task/request and instruction revision, issue/expiry times and revocation state. Bind browser profile and lease epoch where applicable. Capture, use, reveal/export, copying and domain mutation are distinct operations.

An opaque item/profile/connection reference is **never bearer authorization**. Discovery returns only authorized references and host-approved nonsecret labels. Neither a guessed reference nor a formerly valid receipt supplies authority. Reveal/export through the Agent API is disabled in v1; any existing human Vault reveal flow remains separate and cannot forward its output to the Agent. Authorized destination disclosure is a bounded executor operation, not a reveal API.

Immediately before decrypting or dispatching each use, and again before releasing any observation/receipt, the host and executor must reread current grant revision, expiry, revocation, item version/deletion, principal/ACL/scope, task instruction revision, cancellation/hold and lease epoch. Compare against the admitted operation and current destination. Widened instructions require fresh admission; narrowed scope applies immediately. Checking only when queueing or restoring a profile is insufficient. A transactional admission fence and executor-side dispatch fence must serialize takeover/cancellation against new work. An already transmitted effect may be uncertain; revocation cannot undo it, but forbids further use and unauthorized output.

Preserve original SDK job, native task/request/thread, action/operation, effect and provider-object identities across retries, wakeups, capture callbacks and restarts. A delivery/attempt/lease ID is additional identity, not a new logical effect. Store a canonical nonsecret request digest under a scope-bound idempotency key; do not hash raw secrets into public receipts. Identical delivery replays the authorized sanitized receipt without another effect; conflicting content under the same key is rejected. Stale challenge answers must fail revision and original-request checks. If an effect's acknowledgement is lost, preserve `unknown` on the same effect and use the existing domain owner's bounded reconciliation. Never infer failure from lease expiry, invent a new key or blindly retry a purchase/token issuance. Read-only accounting after cancellation does not resume execution. Closing a view stops observation; explicit Stop establishes durable cancellation.

Reversible v1 defaults (host policy may tighten them; changes require a new reviewed policy/grant revision):

| Decision | Default |
| --- | --- |
| Use grant | One item, one exact operation/destination and one logical effect; maximum 5 minutes, also bounded by task/item expiry. No automatic renewal or wildcard scope. |
| New Agent secure-entry challenge | One successful submission; 15-minute maximum, current original-request binding. A shorter Agent deadline may wrap native input; native creation currently uses a 24-hour deadline, which this document does not change. |
| Lease | One human **or** agent owner; 60-second expiry, renewal at most every 20 seconds under current authority; expiry permits no further action until safely reclaimed. |
| Secret output | Deny by default; allow only typed sanitized receipts. General screenshots, files, raw network/DOM/debug data are disabled during sensitive work until separately qualified. |
| Profile retention | Explicit opt-in per scope, encrypted at rest, 24-hour idle limit and 7-day absolute limit, bounded by narrower native/provider policy. Persistence grants no future use authority. |
| Audit/error bounds | Fixed error code and generated correlation ID, message at most 256 characters, audit event at most 2 KiB. Drop unrecognized fields; no arbitrary error string interpolation. |

These defaults do not alter the project's password creation, MFA or authentication-rate-limit requirements; the effective host requirements remain authoritative.

## 5. Browser destinations, custody and lease fences

For every fill/capture/request, bind the exact normalized HTTPS origin (scheme, hostname and effective port), verified provider account, top-level document/navigation generation, full frame ancestry and frame origin, and a unique field identity/type plus form action or request endpoint. A selector or visible label alone is insufficient. Reject opaque origins, ambiguous/replaced fields, unapproved cross-origin frames, script/URL injection and target changes between validation and dispatch. Every redirect, navigation, popup, frame replacement, form-action change or account switch invalidates prior bindings; revalidate the full chain before another action or observation. A login redirect may navigate only along explicitly permitted hops and receives no automatic permission to carry a secret. If the executor cannot atomically bind an action to the validated document, disable secret fill/capture there. Deny unapproved network destinations, including script-driven secret exfiltration; if that cannot be enforced for a page, the sensitive operation is unsupported.

Cookies, refresh tokens, local/session storage, IndexedDB and other persistent profile artifacts are credential custody. Persist only a bounded allowlist in authenticated encryption with profile ID, tenant/user/project/account/environment, schema and key version bound to the ciphertext. Use fresh isolated contexts; never use a worker's default/shared profile, copy a profile between accounts/environments, or hand raw profile archives to tools. Restore only under current authority and an exclusive lease; verify actual logged-in account before use. Keep transient plaintext in a restricted executor sandbox, exclude it from crash dumps, backups and diagnostics, and remove it on close/crash recovery. Nonqualifiable plaintext disk caches disable persistence. Session revocation denies local restore immediately; provider-side invalidation, where available, is a separately authorized native operation, not a promise of universal remote logout.

Lease state is durable and scoped to the profile. Acquisition/takeover uses compare-and-swap with a monotonically increasing fencing epoch and explicit owner kind/identity. Each browser command, secret dispatch, profile write and output release carries the epoch. Human takeover revokes agent access before connecting the authenticated human session; human streams cannot feed the model or recordings. Handback closes human control, increments the epoch and revalidates scope, account, destination and grants; it does not revive a previous grant. Concurrent takeovers yield one owner. Expiry/crash/partition fences the old worker and discards its late results. Before reuse, prove the prior context can no longer act; if the executor cannot fence it, quarantine that profile and fail closed. Preserve unknown effects for reconciliation even after terminating a browser. Cancellation closes/isolates the session, fences all pending operations and suppresses output; late workers cannot save cookies or resume the job.

## 6. Encryption and key lifecycle

Use a host-selected qualified key adapter; this document selects no paid service. Require authenticated encryption, unique nonces, explicit algorithm/envelope/key versions, integrity-bound item/profile and scope identifiers, and separation of key material from ciphertext and model-accessible storage. Check authorization **before** requesting decryption. Never interpret successful decryption as authorization. A wrong tenant's valid ciphertext must fail the scope binding, not merely decrypt under a shared master key.

Rotation must support new-write/old-read key versions, atomic versioned re-encryption or rewrapping, compare-and-swap on current item/profile versions, resumable progress and verification before old-key retirement. No fallback to a development key, unknown key ID, unauthenticated legacy plaintext or trial-decryption across all keys. Decryption outage or integrity failure returns a bounded unavailable result with no raw crypto exception. The native single-key helper is not evidence that these requirements are met.

Deletion first revokes use and fences live executors, then removes ciphertext, transient copies, cached credentials and profile descendants; retain only allowlisted tombstone/audit metadata. Key destruction must not accidentally destroy unrelated tenants' items sharing a key. Document backup retention and enforce deletion/revocation tombstones against restored backups. Recovery requires independently authenticated host authority, approved key access and current durable revocation/cancellation/lease state; if current tombstones cannot be established, do not decrypt/restore. Backup restore never resurrects grants, deleted items, expired challenges or old lease epochs. Prove isolation, rotation interruption, retirement, deletion and recovery using synthetic values before enabling custody.

## 7. Observation, errors and evidence

Apply an executor-side output gate **before** any stream, serializer, tool return, diagnostic sink, model call, chat/history write or retained evidence. Treat all destination responses as tainted, including responses generated before revocation. Reauthorize the recipient and operation immediately before release. Validation inside a prompt, regex matching only known passwords, or masking `<input type=password>` cannot establish safety. Allowlisted schemas and host-generated status facts are the default; values derived from arbitrary page/provider text are not trusted metadata.

| Channel | Fail-closed policy |
| --- | --- |
| DOM, page text and accessibility | No raw DOM, hidden attributes, field values, scripts, accessibility names or arbitrary evaluation results. Emit only independently verified, typed facts. Reflections, split/encoded/transformed values and previously unknown secrets must be covered; if safe filtering cannot be established, withhold the entire observation. |
| Screenshots/video/human takeover | Disabled for sensitive sessions unless a qualified pre-release pipeline establishes the whole frame is safe, including canvas, overlays, popups and cross-origin frames. Cropping/password masking/OCR alone is not proof. Keep private human interaction outside model streams; no raw recordings. |
| Downloads/uploads/clipboard | Deny by default. A separate qualified transfer checks current authority, destination, type/size and sanitized content in isolation. Raw downloads stay out of model/evidence stores; unsupported formats or uncertain filtering are withheld and transient bytes discarded. Never upload a profile, secret file or clipboard through a generic file tool. |
| Network diagnostics | No raw bodies, URLs/query strings, headers, cookies, HAR, WebSocket frames or redirects. Return fixed status classes, approved endpoint IDs and timing buckets only; capture and sign inside the executor without diagnostic taps. |
| Logs/errors/traces | No plaintext, ciphertext dumps, tokens, secret-derived hashes, user-controlled labels, provider error bodies, stack locals or SQL parameters. Normalize to allowlisted codes and generated IDs before any logging, including exception/APM/crash paths and private host sinks. |
| Model observations, chat, task history, callbacks and retained evidence | Reuse only gate-approved typed receipts under current recipient authorization. Evidence records scenario ID, revision, scope-safe correlation IDs and safe pass/fail counts; never raw canary values, screenshots or captured payloads. Gate both live and replayed delivery. |

The audit allowlist is: generated event/correlation ID, authorized opaque item/profile/grant/job/task/effect IDs, grant/policy revision, lease epoch, key version identifier, operation/type enum, approved destination identifier, timestamp, bounded duration bucket and outcome/rejection code. Scope IDs belong only in access-controlled host audit where needed; model receipts receive the smaller authorized subset. Reject free-form titles, filenames, URLs, error messages and arbitrary metadata. Audit is append-only under the native owner and its retention/access policy; loss of a required audit receipt denies a new secret use. Audit availability must not cause raw fallback logging.

Unexpected sensitive content triggers suppression and a fixed `observation_withheld` result, with no partial stream already released. Disable the affected observation capability until qualification covers it. Do not ask the model to inspect the suppressed material. Prevent bypass through shell/filesystem tools, raw CDP/DevTools, network interception, alternate screenshots, profile export, provider dashboards or a human stream routed into model context. Secret-bearing executor memory and raw bytes are not debugging artifacts.
